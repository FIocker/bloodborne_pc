# Windows 1.9.2 integration

Upstream base: `de2e38a` (Windows 1.9.2). Previous fork head: `98cd689`.

The fork changes were rebased onto the Windows release branch. Upstream's
frame-generation replacement remains removed; the fork's paced DLSS/FSR frame
generation, source timing and Reflex implementation remain in place. Their core
implementation files have no changes relative to the previous fork head.

## Upstream changes retained

- Multiple keyboard/mouse bindings and combinations, the Dark Souls III layout,
  device-aware keyboard/PlayStation/Xbox/Switch button prompts, and gesture input.
- Field-of-view adjustment and mute while in the background.
- Texture lifetime, low-VRAM budget and allocation-retry corrections.
- Old-CPU instruction handling, stretched-polygon shader-binding corrections,
  optional duplicate-barrier tracking, and device-loss/crash diagnostics.
- The Hunter's Dream long polling and external FPS-patch precedence.
- Launcher version selection, using the fork's existing update channel.

## Fork features retained

- Paced DLSS/FSR FG, Reflex, motion-vector work, reconstruction and UI composition.
- Native neural rendering, model presets, pass controls and custom toggle hotkey.
- bbhost direct mouse camera, automatic-rotation handling, controller priority,
  lock-on flicks and live game-menu pointer, plus their launcher settings.
- Existing aspect-ratio, resolution, effects, stability and resource-retirement fixes.
- Existing privacy mapping and the fork's update source.

Upstream's newer direct camera also applies motion during the game camera update;
it is an improvement over its earlier implementation. The bbhost camera is still
retained for its full camera-step and lock-on behavior. Only one camera hook
implementation is enabled. Upstream's separate drawn-position synchronization
setting is accepted when reading old files but is not used by the bbhost hooks.

The native camera additionally honors upstream's vertical-sensitivity setting.
The Controls editor preserves combinations and three binding slots for normal
actions. The PC-specific strong-attack modifier and menu confirm/back actions each
retain their single-key or mouse-button binding. Existing layouts are preserved;
the bbhost layout remains an explicit preset.

The upstream FSR per-frame bridge-allocation fix is already covered by the fork's
frame-retirement patch. The redundant patch is omitted rather than applied twice.
RTAO remains excluded.

## Validation

The native Windows build, direct-camera, camera-hook, menu-pointer, input-parser,
pad, button-icon, FG timing/settings, Reflex and neural-settings checks pass.
The hidden launcher integration check verifies Graphics/Controls construction,
preset application, combined mouse/binding saves, multiple bindings and a second
save through the existing callbacks.

The Python suite runs 257 tests: 202 pass, 49 are skipped, and six fail due to
Windows symlink privileges and Linux-oriented shell/driver fixtures. The same six
failures reproduce on unmodified upstream `de2e38a` in this environment.

Gameplay smoke checks and presentation captures are recorded with the local build
artifacts. These are regression checks, not a new latency benchmark or a long
stability soak. No change to Reflex's measured latency benefit is claimed here.
